# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

It is a **working document**: it holds the project's shared context, not just the reference below. A fresh session with no memory should be able to read this file and pick up where the last one stopped.

## Rules for Claude (read first)

1. **Start of session:** read *Current state* and *Open threads* below before doing anything else. Treat them as the handoff from the previous session. Verify anything that names a file, function or flag before relying on it, since the code may have moved on.
2. **Mirror memories here.** Whenever you save, update or delete a memory in this project's Claude Code memory directory (`~/.claude/projects/<this-project>/memory/`), make the same change in *Project context* below **in the same turn**. The memory directory is local to one machine; this file travels with the repo, so it is the source of truth.
   - Mirror `project`, `feedback` and `reference` memories. Keep `user`-type memories (personal details about the user) out of this file, because the repo is public.
   - One bullet per memory, tagged with its type and date. For `feedback`/`project` entries, keep the **Why** so a later session can judge edge cases.
   - If a memory turns out to be wrong, remove it from both places.
3. **Keep the handoff current.** Before ending a piece of work (or when the user wraps up), update *Current state*, *Open threads* and add a dated entry to the *Session log*. Write it for a reader with zero context: say what was done, what's half-done, and what the next concrete step is.
4. Use absolute dates (YYYY-MM-DD), never "yesterday" or "last week".
5. Edits to this file are normal changes: include them in commits alongside the code they describe. Don't commit or push unless the user asks.

## What this is

A KOReader plugin (Lua 5.1 / LuaJIT) that suppresses Wi-Fi lifecycle popups, shows a corner status icon and a tappable menu-bar Wi-Fi icon instead, and bundles a non-blocking Wi-Fi connect engine for Kobo. Only `main.lua`, `wificonnect.lua`, `wificonnect_kindle.lua` (loaded only on Kindle) and `_meta.lua` ship at runtime; there is no build step. On the device the folder is `wifistatus.koplugin/` (renamed from `wifiindicator.koplugin` on 2026-09-29, branch `release-setup`). Releases: `.github/workflows/release.yml` builds `wifistatus.koplugin.zip` on a `vX.Y.Z` tag push, and the tag must equal `_meta.lua`'s `version`.

## Tests

```sh
luajit test/test_main.lua main.lua   # plugin: popup filter, menu icon, status presenter, settings
luajit test/test_wificonnect.lua     # engine: pure hand-off logic
luajit test/test_engine.lua          # engine: simulated connect flows
```

- Run from the **repo root**: `main.lua` does `require("wificonnect")`, which only resolves via `./?.lua`.
- There's no test framework and no single-test selection: each file is a script of `check(cond, label)` calls printing PASS/FAIL, exiting non-zero on any failure.
- `test_main.lua` stubs every KOReader module via `package.preload` and a global `G_reader_settings`. When `main.lua` gains a new `require`, add a matching stub. Its `ui/network/manager` stub has no `wpa_supplicant`, so the engine doesn't install there.
- `test_engine.lua` runs the real `wificonnect.lua` against a fake NetworkMgr, a fake wpa_supplicant (`WpaClient`), inline "subprocesses" that restore `NetworkMgr` afterwards (to emulate fork isolation), a fake `ffi`, and a virtual clock (`run()` drains `UIManager:scheduleIn`). It checks flow and bookkeeping, not hardware timing. It polyfills `table.pack`, because KOReader's LuaJIT has Lua 5.2 compat and a stock desktop LuaJIT doesn't.
- No `luacheck` on the dev machine. `luajit -bl <file> /dev/null` is a quick syntax check.

## Releasing

1. Bump `version` in `_meta.lua` (e.g. `2.0.1`) and commit.
2. `git tag vX.Y.Z && git push origin main vX.Y.Z`
3. `.github/workflows/release.yml` runs the three suites, checks the tag equals `v` + the `_meta.lua` version, zips `wifistatus.koplugin/{main,wificonnect,wificonnect_kindle,_meta}.lua`, and publishes the release (`gh release create --generate-notes`). Watch it with `gh run watch`.

Storefront's hourly catalog rebuild picks up new releases. A failed check publishes nothing; delete and re-push the tag after fixing.

## Architecture

KOReader has no hooks for this, so everything works by **monkey-patching KOReader at load time**, not in `WifiIndicator:init()`.

- **Load-once guards.** KOReader instantiates the plugin twice (FileManager and ReaderUI). `main.lua`'s patches store the original under a `_wifiindicator_orig_*` field and only wrap if it's absent. `wificonnect.install()` is guarded by `NetworkMgr._nbwifi_installed`. Shared state (the corner icon frame) is module-level. The test "double plugin load still injects exactly one icon" guards this.
- **`main.lua`**
  - **`LOOKS`** is the single table that decides how each state looks: its KOReader icon (used by both the corner and the menu bar) and `corner` seconds (no `corner` = menu bar only). States: `off`, `on` (Wi-Fi on, not connected), `connecting` (stays up; 90 s is only a safety cap), `connected`, `problem` (warning triangle). Keep presentation choices here.
  - **Corner:** `presentStatus(state)` is fed by the engine (`wificonnect.on_status`), the `onNetworkConnected`/`onNetworkDisconnected` handlers, and intercepted popups. States without a corner look (e.g. `choose`, `idle`) hide it. Showing the same icon again only restarts its timer (no extra e-ink refresh).
  - **Menu bar:** `menuState()` combines KOReader's live state (`isConnected`/`isWifiOn`) with `wificonnect.state` (connecting is checked before `isWifiOn`, because the radio is off during bring-up; `problem` only shows while Wi-Fi is on and not connected). It's refreshed on menu open, on `updateItems`, and live on every status change via `refreshMenuIcon()` (called from `presentStatus`; it only touches the last menu that got the icon, and only while `UIManager:isWidgetShown(menu.show_parent)`). KOReader `dofile`s `main.lua` once per run (`PluginLoader:loadPlugins` caches), so module-level state is shared; the first load alone wires `wificonnect.on_status` (`_wifiindicator_wired`), matching the other load-once guards.
  - Wraps `UIManager.show` to drop `InfoMessage`s whose `text` matches `INTERCEPTED_MESSAGES` (each entry maps to a presenter `state`). Entries must be the *exact* source strings from KOReader, wrapped in `_()` so gettext resolves them to the same translation; `msgToPattern` turns `%1` into a wildcard. If KOReader changes its wording, update this list.
  - Wraps `TouchMenu.init` / `TouchMenu.updateItems` for the menu-bar icon. Tapping broadcasts `ToggleWifi`.
  - Network event handlers must **not** return `true` (other listeners need the events).
- **`wificonnect_kindle.lua`** (Kindle backend, loaded by `wificonnect.install()` only on a Kindle with lipc): it receives the shared core (`NetworkMgr`, `enabled`, `report`, `start`, `pollUntil`, `scanNetworks`, `showList`) and replaces `reconnectOrShowNetworkMenu` only. **Gotcha:** KOReader adds the plugin folder to `package.path` only while it `dofile`s `main.lua`, so plugin-local `require`s must happen at load time (as `install()` does), never lazily from a callback.
- **`wificonnect.lua`** (see `docs/plan-wpa-handoff.md` for the why). The top part is pure, tested logic (`decodeSSID`, `toHex`, `needsPsk`, `networkParams`, `pickNetworks`, and `mergeBySSID` for the list the engine shows). `M.install()` hooks `NetworkMgr` only on a **Kobo** with `NetworkMgr.wpa_supplicant` set (Kobo-only since 2026-09-30; Cervantes, reMarkable and Sony PRS also use wpa_supplicant but were never tested, so they keep stock connecting):
  - Entry points: `turnOnWifi` (bring-up, then connect), `reconnectOrShowNetworkMenu` (connect), `restoreWifiAsync` (wake/startup), and the network list's `NetworkItem:connect`. `NetworkItem` is module-local in KOReader, found via `debug.getupvalue(NetworkSetting.init, …)` and patched lazily the first time the engine shows the list. Each entry point falls back to stock when the `wifiindicator_nonblocking_wifi` setting is off.
  - Flow: `bringUp` (stock `turnOnWifi` in a subprocess with reconnect stubbed) → `handOff` (add KOReader networks wpa_supplicant doesn't know; psk derived once and saved) → `joinAndGetIP` (poll `getConnectedNetwork` up to 15 s, then `obtainIP` in a subprocess, then set `lease_ssid`). If `handOff` finds nothing for wpa_supplicant to try, it skips the join wait. On failure (`giveUp`): interactive → report `choose` (or `problem` if DHCP failed), scan in a subprocess and show the network list; non-interactive → `_abortWifiConnection()` after reporting `problem`, except a wake/startup restore that found nothing, which reports a quiet `off`. The engine keeps its latest state in `M.state`; a teardown during `connecting` resets it to `idle`.
  - Returning `nil` from `turnOnWifi` means "pending" to `NetworkMgr:enableWifi()`; on failure the engine must call `_abortWifiConnection()` itself. `complete_callback` schedules KOReader's connectivity check (which broadcasts `NetworkConnected`).
  - `gen` counter: bumped by wrapped `disableWifi`/`_abortWifiConnection` and by each new attempt (latest wins). `subprocessCall` and `pollUntil` drop their callbacks when it changes.
  - Never use `ffiutil.readAllFromFD()` on subprocess pipes: Wi-Fi scripts spawn daemons that inherit the write end, so it would hang the UI thread forever. Use `drainPipe` (FIONREAD-based).
  - The engine shows no popups, except "Timed out" when a network tapped in the list fails to join.

## Settings

All in `G_reader_settings`, default-on via `nilOrTrue` / `flipNilOrTrue`: `wifiindicator_suppress_popups`, `wifiindicator_show_icon`, `wifiindicator_menu_icon`, `wifiindicator_nonblocking_wifi` (the engine's kill switch). Menu labels (since `menu-labels`): Connect in the background / Hide Wi-Fi popups / Show Wi-Fi status in corner / Show Wi-Fi status in menu bar, plus the "Show network list" action (`wificonnect.showNetworkList`), under "Wi-Fi status & connect". `settingItem()` in `main.lua` builds each checkbox. Settings are keyed by these fixed strings, so renaming the `.koplugin` folder does NOT reset them (an earlier chat claim that it would was wrong). KOReader names the plugin after its **folder** (`PluginLoader` sets `plugin_module.name` from the folder, overriding `main.lua`'s `name`); only per-plugin KOReader state such as `plugins_disabled` is keyed by the folder name. (A second earlier claim, that KOReader identifies the plugin by its internal name, was also wrong.) Don't leave two copies installed. When adding a setting, also add it to `WifiIndicator:deletePluginSettings()` and update the test that asserts the full key list.
